# Release Verification

Use this guide to help users verify that a GitHub release matches the public source.

## What Maintainers Should Publish

Each release should include:

- Git tag and commit SHA.
- APK SHA-256 hash.
- `RELEASE_MANIFEST.json` with the source commit, package variant, APK filename, byte size, hash, build command, SDK levels, and signing certificate fingerprint when available.
- Build command used for the artifact.
- `SHA256SUMS.txt` generated by `scripts/package-debug-release.*` or `scripts/package-signed-release.*`.
- Device test matrix from `docs/TEST_PLAN.md`.
- Known limitations and security notes.
- Signing certificate SHA-256 fingerprint for signed APK releases.

## Build From Source

Clone the repository, check out the release tag, install JDK 17 and Android SDK platform 35, then run:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

On macOS or Linux:

```bash
bash ./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

To reproduce the debug test package layout:

```bash
bash ./scripts/package-debug-release.sh v0.1.0
```

To reproduce a signed APK, configure the `AIRCHAT_KEYSTORE`, `AIRCHAT_KEYSTORE_PASSWORD`, `AIRCHAT_KEY_ALIAS`, and optional `AIRCHAT_KEY_PASSWORD` environment variables, then run:

```bash
bash ./scripts/package-signed-release.sh v0.1.0
```

## Compare APK Hash

Start with the release manifest:

```bash
cat release/RELEASE_MANIFEST.json
```

Confirm that `sourceCommit` matches the GitHub tag commit, `apk.file` matches the downloaded APK, and `apk.sha256` matches `SHA256SUMS.txt`.

On Windows:

```powershell
Get-FileHash app\build\outputs\apk\debug\app-debug.apk -Algorithm SHA256
```

On macOS or Linux:

```bash
shasum -a 256 app/build/outputs/apk/debug/app-debug.apk
```

For signed releases, also compare the signing certificate SHA-256 fingerprint in `release/RELEASE_NOTES.md` against the fingerprint published in the GitHub Release.

For early debug releases, byte-for-byte APK reproducibility is not guaranteed because Android build tooling can embed local metadata. Treat matching source, passing CI, a published APK hash, draft-release artifacts, and a documented field-test matrix as the minimum trust baseline.
